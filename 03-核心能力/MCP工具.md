# MCP 工具与 MCP 广场

## 定位

MCP 是企业工具的标准化接入层。MCP 广场负责让内外部 MCP Server 被发现、管理、鉴权、复用和运行监控，缓解政企老旧系统与业务 API 的碎片化问题。

## 路线能力

| 基础能力 | 扩展能力 |
| --- | --- |
| MCP 广场、自定义 MCP 服务、管理、鉴权 | 远程调用、客户自带 API Key、内部 MCP、运行时监控、工具集 |

## 端到端职责

1. 管理员注册 MCP Server，声明工具、鉴权方式、服务地址、租户范围与可用性。
2. Agent Runtime 根据 Agent 配置和用户请求发现可用工具，并由模型选择调用。
3. MCP 网关完成身份传递、调用审计、限流、重试和错误分类。
4. 工具结果回到 Runtime；必要时经 Sandbox 对结果文件/代码进行受控处理。

## 与 Sandbox 的边界

- MCP 解决“如何以标准协议接外部系统”；Sandbox 解决“如何安全执行代码、浏览器和文件动作”。
- 某个 MCP 工具若只是远程 API 调用，不必为了调用本身进入 Sandbox；若返回脚本、文件或要求本地执行，则应由 Sandbox 处理。
- 二者共同需要统一的租户、权限、Trace 和审计 ID，才能完整回答“哪个 Agent 在何时以什么身份调用了什么能力”。

## 安全与治理

- 禁止模型直接拥有长期高权限 API Key；使用租户/用户/Agent 维度的凭据代理或短期 Token。
- 工具输入输出进行数据分级、脱敏、大小限制和审计。
- 在 MCP 目录中记录工具版本、所有者、SLA、限流、风险等级和弃用状态。

# 可观测与 Agent 评测

## 目标

将 Agent 的“是否运行、为何失败、是否答对、花了多少、能否复现”变成可观察和可度量的问题。立项材料提出 Langfuse 集成、运行/资源/事件监控，以及知识库、记忆库、Sandbox 的可观测性；评测资料补充了 Trace 自动采集、数据集、LLM/代码评估器、线上/离线评测和实验统计。

## Trace 最小结构

```text
Root Span（一次用户任务）
├── Model Span（模型调用、Token、延迟）
├── Retrieval Span（知识/记忆检索、命中与引用）
├── Tool Span（MCP 调用、参数摘要、状态）
└── Execution Span（Sandbox/Skill、资源、退出码、产物）
```

## 评测闭环

1. 从真实 Trace 或人工任务创建评测数据集。
2. 定义评价维度：任务完成、事实正确、安全合规、工具选择、成本和时延。
3. 选择 LLM 评估器、代码评估器或人工评审；高风险结论需人工复核。
4. 在部署版本上执行离线或在线实验，对比结果明细与指标统计。
5. 将失败样本回流到 Prompt、Skill、MCP、Sandbox 策略、知识库分块或模型配置。

## 必须关联的指标

- 质量：任务成功率、引用正确性、工具调用正确率、评测分数。
- 性能：端到端时延、模型/检索/工具/Sandbox 分段时延、排队与冷启动。
- 成本：Token、运行实例、Sandbox 资源、存储、网络、工具调用。
- 可靠性：错误率、超时率、重试率、降级率、告警恢复时长。
- 安全：拒绝率、越权尝试、敏感数据命中、异常出网和权限变更。

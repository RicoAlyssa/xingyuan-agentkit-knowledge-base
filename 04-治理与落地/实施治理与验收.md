# 实施、治理与验收

## 建议实施顺序

1. **运行时最小闭环**：建立 Agent 入口、CLI/SDK、部署、会话、Trace 和基本资源监控。
2. **安全执行闭环**：上线受限 Sandbox 模板、实例生命周期、审计与回收；先覆盖代码/文件/浏览器的高风险执行。
3. **工具接入闭环**：以 MCP 接入低风险只读工具，再逐步引入写操作和客户自带凭据。
4. **复用闭环**：建设 Skills 空间、版本、审批、SkillHub 与沙箱执行策略。
5. **智能数据闭环**：接入知识库、记忆库，完成数据隔离、引用、策略和监控。
6. **质量与商业闭环**：评测数据集、线上实验、成本归因、账单和告警。

## 风险登记册

| 风险 | 影响 | 首要控制 |
| --- | --- | --- |
| Agent 生成/执行恶意代码 | 高 | Sandbox 隔离、资源/网络限制、最小权限、审计与自动回收 |
| MCP 凭据越权或外部工具误操作 | 高 | 凭据代理、工具分级、审批、幂等/确认机制、审计 |
| 跨租户检索或记忆泄露 | 高 | 租户命名空间、访问控制、检索过滤、数据加密、渗透测试 |
| Skill 供应链污染 | 高 | 内容哈希、签名/审批、依赖锁定、沙箱执行、快速撤回 |
| 模型幻觉或错误自动化 | 中高 | 知识引用、评测、人工确认阈值、操作前校验 |
| Serverless/Sandbox 成本失控 | 中高 | 配额、超时、预热池策略、按 Trace 成本归因、预算告警 |
| 可观测数据含敏感信息 | 中高 | 脱敏、字段分级、访问控制、保留期和审计 |

## 分层验收

### Runtime

- [ ] 新版本可部署、回滚，并能观察实例、资源、事件与 Trace。
- [ ] 工具、检索、Sandbox 的错误被准确归类并返回可行动信息。

### Sandbox

- [ ] 通过 [沙箱专题验收清单](../03-核心能力/沙箱Sandbox.md#10-验收清单)。
- [ ] 至少完成一次越权存储、异常外联、资源耗尽、恶意/错误 Skill 的负向测试。

### MCP 与 Skills

- [ ] 工具和 Skill 的发现、授权、版本、回滚、审计可闭环。
- [ ] 高副作用操作支持用户确认或策略审批。

### 知识、记忆与评测

- [ ] 回答可展示来源或明确“未检索到可靠依据”。
- [ ] 记忆可查看、修改、删除，且不会跨用户/租户泄露。
- [ ] 每次发布有固定评测集、质量门槛与成本/时延回归比较。

## 上线门禁建议

- 每个模板、MCP、Skill 和模型配置都有所有者与回滚方案。
- 高权限操作默认关闭，采用最小权限、短期凭据和显式审批。
- 对外部网络、对象存储、日志和下载产物实行可配置的数据保留策略。
- 任何“降级”都需要告警或仪表盘，而不是不可见地失效。

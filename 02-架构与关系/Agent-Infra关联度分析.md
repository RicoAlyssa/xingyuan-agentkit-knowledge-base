# Agent Infra 关联度分析

## 结论

**Agent 运行时（AgentEngine Runtime）与 Agent Infra 关联最大。**

它是所有 Agent 请求的承载与调度中枢：负责部署、实例生命周期、底层资源选择、运行监控、事件告警，并把模型、工具、Sandbox、记忆和知识能力组装成可运行的任务链路。没有 Runtime，其他组件仍可作为独立服务存在；没有 Runtime，它们无法形成可部署、可扩缩、可治理的 Agent 产品。

## 为什么 Sandbox 紧随其后

Sandbox 是 **Agent Infra 中最关键的安全执行子系统**。它不负责总体编排，却决定 Agent 是否能安全地执行代码、浏览器自动化、终端命令、文件处理和 Skill 脚本。对于高合规客户，Sandbox 往往是平台是否可被采用的准入能力。

## 关联度排序（分析判断）

| 排名 | 板块 | 与 Agent Infra 的关系 | 说明 |
| --- | --- | --- | --- |
| 1 | Agent Runtime / AgentEngine | 核心 | 部署、生命周期、调度、资源、运行与控制面的连接点。 |
| 2 | Sandbox | 核心执行子系统 | 隔离执行、实例、镜像、存储挂载、网络与日志，是安全与可执行性的底座。 |
| 3 | 可观测与评测 | 平台治理底座 | 让 Runtime 和工具链可运营、可度量、可优化。 |
| 4 | MCP | 标准化接入层 | 把外部企业系统接入 Agent，但通常依赖 Runtime 编排和权限治理。 |
| 5 | Skills 中心 | 能力分发层 | 标准化能力包的发现、授权、下载与版本更新。 |
| 6 | 记忆库、知识库 | 智能数据服务层 | 提供上下文和事实检索，是 Agent 能力增强而非执行底座。 |

## 判别方法

一个组件越符合以下条件，越接近 Agent Infra：

1. 多数 Agent 都必须依赖它才能部署、运行或扩缩。
2. 它管理资源、隔离、网络、存储、身份、生命周期或可观测性。
3. 它的故障会造成跨应用的系统性不可用，而不仅是单项功能降级。
4. 它可为不同模型、框架、Skill 和业务 Agent 复用。

Runtime 满足四项；Sandbox 满足后面三项且直接承担高风险执行，因此二者应作为架构、资源与安全投资的优先级最高组合。

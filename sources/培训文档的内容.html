前置概念：用大白话先搞懂这些词

如果你是第一次接触 Agent 开发，别被一堆英文缩写吓到。下面这些词在后面会反复出现，先建立直觉。

智能体 Agent
能自己「决定调哪个工具、怎么回答」的 AI 程序。不只是聊天，而是会行动。
函数调用 Function Calling
模型能「决定调用某个工具」并给出参数。这是 Agent 能动手的基础。
LangGraph
LangChain 出品的 Agent 框架。用图（graph）编排「思考-调用工具-观察」循环，create_react_agent 一行造出 ReAct 智能体，自动管工具调用循环。
create_react_agent
LangGraph 的开箱即用 ReAct Agent 工厂。传入模型+工具即得一个 compiled graph，自动处理「模型决策→调工具→把结果喂回模型」的循环。
ksadk 金山云 Agent SDK
金山云的 Agent 运行时平台。提供知识库、记忆库、沙箱、MCP、部署、Trace 等基础设施，import 即用。
ChatOpenAI
langchain-openai 的模型封装。无论 glm、deepseek 还是 GPT，都走同一套 OpenAI 兼容接口，换模型不改代码。设 streaming=True 即可流式。
compiled graph
LangGraph 编译后的可运行图。本培训里就是 create_react_agent 的产物，也是平台加载的 root_agent。
RAG 检索增强生成
先去知识库查相关文档，再让模型基于查到的内容回答。让回答「有来源、不胡说」。
MCP Model Context Protocol
一个标准协议，把任意接口变成 Agent 能调用的工具。统一格式，即插即用。
沙箱 Sandbox
隔离的安全运行环境。把代码丢进去跑，跑完销毁，不影响主系统。
SSE Server-Sent Events
服务器向浏览器单向推消息的协议。模型一边生成一边推，前端看到打字机效果。
root_agent
你 Agent 的「主入口变量」。平台通过它加载并运行你的 Agent。
preload_memory
记忆库的预检索。每轮对话前自动把相关历史记忆塞进系统提示，模型不用主动调。本版用 LongTermMemoryService 实现，等价于 ADK 版的 preload_memory 工具。
优雅降级 Graceful Degradation
某个可选能力（如记忆库）没配或失败时，静默跳过，不让整个 Agent 崩掉。
一句话记住：LangGraph 是「怎么写 Agent」的框架，ksadk 是「怎么跑/部署/观测 Agent」的平台，ChatOpenAI 是「怎么接模型」的封装，MCP 是「怎么接工具」的协议。络络把它们组合起来。
第一篇

设计：先想清楚做什么、怎么分层

别急着写代码。设计阶段回答三个问题：智能体为谁、能做什么、属于哪一类；然后定架构、做决策。

1.1

定位：给智能体一个清晰的身份

这一步在做什么：动手前先想清楚——你的 Agent 给谁用、解决什么问题、属于哪一类智能体。定位会直接写进 Agent 的人格指令里，指令越明确，模型越不会乱发挥。
为谁服务
金山云用户：查产品文档、查计费数据、算计费价格。
核心能力
会查（知识库+计费数据）、会算（价格计算）、会记住（用户偏好）。
智能体类型
响应型（Reactive / Tool-Calling）—— 确定性强、可溯源，非自主规划型。
分界线
应用自己写：人格指令、计费规则、偏好 schema、UI。
平台提供：检索/记忆/沙箱/运行时。
agent.py · AGENT_PROMPT AGENT_PROMPT = """你是络络，智能知识助手。 【能力】1) 知识库检索 2) 计费数据查询 3) 计费价格计算 【必须调用知识库】每个问题都先查库，即使自认知道答案 【计费计算规则】EIP/BWS/NAT… 地域别名自动识别 【记忆】用户偏好默认参数优先使用 【引用格式】> 来源: 文档 | 切片: id | 相关度: % """
培训要点：定位不是 PPT 口号，它会直接落到 Agent 的 instruction 里。指令越明确，模型越可控可溯源——这是响应型智能体可靠性的根源。

1.3

四项关键设计决策（附理由）

这一步在做什么：技术选型不是选「最好的」，而是选「代价你能接受的」。下面四个决策都标了为什么选和代价是什么。
① Agent 框架选 LangGraph

create_react_agent 一行造出 ReAct 智能体，自动管「模型决策→调工具→喂回结果」循环；astream_events 原生流式；ChatOpenAI 统一多模型。ksadk 另支持 Google ADK/LangChain/DeepAgents，可按团队栈换。
代价：compiled graph 无状态，每轮上下文要自己注入。

② MCP 自建 HTTP/JSON-RPC

不用 ADK 内置 McpToolset（依赖本地 MCP 进程，失败会阻塞 Agent）。自建可优雅降级、格式化返回、追加 Excel。
代价：自己维护协议封装代码。

③ 流式选 SSE 非 WebSocket

SSE 单向（服务器→浏览器）已足够流式输出；FastAPI 原生支持；前端 fetch+ReadableStream 即可消费。
代价：单向，不能客户端→服务器推。

④ 存储用 SQLite 非 PostgreSQL

开发期零配置、文件即库、适合迭代。
代价：并发写入弱；用户量增长后再迁 PostgreSQL。

培训要点：关键不在于哪个「最优」，而在于优雅降级——可选能力失败不阻塞主链路。这是络络高可用的设计哲学，也是新手最容易忽略的一点：别让一个组件的故障拖垮整个 Agent。
第二篇

开发：逐组件把能力接进来

从环境准备开始，搭 Agent 骨架，再把知识库、MCP、沙箱、记忆、流式五项能力逐个接入。每节都标「这一步做什么 + 需要的环境变量」。

2.1

环境准备：ksadk 是底座，LangGraph 是框架

这一步在做什么：装好两个东西——ksadk（金山云平台底座 + 命令行）和 langgraph + langchain-openai（Agent 框架 + 模型封装）。装完用 agentengine -version 验证。

requirements.txt 关键依赖 langgraph>=1.0.0 # create_react_agent 框架 langchain-openai>=1.0.0 # ChatOpenAI 模型封装 langchain-core>=0.3.0 # SystemMessage/HumanMessage/StructuredTool ksadk>=0.6.0 kingsoftcloud-sdk-python # 知识库/记忆库底座，不装静默失败 openai>=1.0.0,<2.0.0 # langchain-openai 依赖；<2 避免序列化告警 e2b>=2.0.0 # 沙箱 E2B 协议底座 openpyxl>=3.1.0 # 计费明细 Excel 导出 email-validator>=2.0.0 # FastAPI EmailStr
避坑（真实踩过的）：kingsoftcloud-sdk-python / email-validator 是「隐式依赖」——不显式声明会静默失败（不是报错，是功能悄悄不工作）。注意 openai<2.0.0 也要锁，langchain-openai 同样依赖 openai<2，否则序列化告警。培训第一课：把隐式依赖显式写进 requirements。
下一步：装好后把项目根目录的 .env.example 复制成 .env，后面每一节会告诉你该填哪些变量。本文档附带一份带详细注释的模板：下载 luoluo.env.example（右键另存，或直接在浏览器打开查看）。
2.2

Agent 骨架：定义人格、模型、工具

这一步在做什么：用 LangGraph 的 create_react_agent 把「模型 + 工具 + 人格指令」组装成一个可运行的 compiled graph。骨架就这几行，难点在「工具怎么造」和「平台怎么接」。
agent.py · 真实骨架 from langgraph.prebuilt import create_react_agent from langchain_openai import ChatOpenAI from langchain_core.messages import SystemMessage from ksadk.knowledge_base.langchain_tool \ import search_knowledge_base from mcp_billing_tools \ import queryMeasureSummary, queryMeasureDetail from sandbox_billing_tool \ import calculate_billing as calc_billing def get_compiled_graph(): model = create_model() # ChatOpenAI(streaming=True) tools = [search_knowledge_base, queryMeasureSummary, queryMeasureDetail, calc_billing] return create_react_agent( model=model, tools=tools, prompt=SystemMessage(AGENT_PROMPT)) root_agent = get_compiled_graph() # compiled graph
①
模型走 ChatOpenAI：OpenAI 兼容接口，设 streaming=True，换模型只改环境变量。
②
工具即列表：ksadk 工具（知识库）与自建工具（MCP/沙箱）平级挂载，沙箱纯函数用 StructuredTool 包装。
③
人格随消息传：compiled graph 无状态，人格以 SystemMessage 每轮注入，历史走 DB。
④
记忆预检索：每轮前用 LongTermMemoryService 检索历史记忆，追加进系统提示。
⑤
root_agent 入口：模块级 compiled graph，供平台 runner 加载（第三篇细讲）。
读法提示：别被 import 吓到。第一行是 LangGraph 的 ReAct 工厂，第二行是 ChatOpenAI 模型封装，第三行是 ksadk 的知识库工具——就是「框架 + 模型 + 平台工具」三件套。create_react_agent 自动处理「模型决定调哪个工具→调用→把结果喂回模型」的循环。

2.4

能力 2 · MCP 计费查询：存量接口即插即用变工具

这一步在做什么：你公司已经有一堆现成的 HTTP 接口（比如查计费），不想为每个接口重写适配层。MCP 是个标准协议，按它的格式包一层，所有接口就变成 Agent 能统一调用的工具。
真实请求结构（自建 JSON-RPC） payload = { "jsonrpc": "2.0", "id": 1, "method": "tools/call", "params": { "name": "queryMeasureSummary", "arguments": { "businessLine": "eip", "start": "202604010000", "end": "202604012359", "region": "华北1（北京）", "uid": "12345", "isp": "BGP" } } } # httpx POST → MCP_BILLING_URL
①
统一协议：所有计费接口走 JSON-RPC tools/call，不必每接口写适配层。
②
优雅降级：连接失败/超时返回友好提示，不阻塞 Agent 其他能力。
③
字段重映射：原始 in95/out95/flowSum → 中文指标「入带宽95分位」。
④
附加价值：Detail 查询附加 Excel 导出（billing_detail_*.xlsx）。
!
关键决策：不用 ADK McpToolset，因其依赖本地 MCP 进程、失败会阻塞整个 Agent。
📋 本节需要的环境变量（写进 .env）
MCP_BILLING_URL 必填MCP 计费服务地址，如 https://xxx.aipro.ksyun.com/mcp。不填则应用启动直接报错（config.py 强校验）。
MCP_BILLING_BEARER 必填MCP 访问令牌（Bearer Token）。不填则应用启动直接报错。⚠️ 密钥，勿提交。
培训要点：MCP 是「把存量接口变 Agent 工具」的标准协议。络络自建薄封装而非用框架内置——换来降级能力和对返回格式的精细控制。代价是自己维护协议代码。
2.5

能力 3 · 沙箱 Skill：业务代码投进沙箱算

这一步在做什么：计费算价逻辑（规则表、阶梯价）是你写的业务，但要跑在不安全的环境里就有风险。沙箱是个隔离的「保险箱」——把代码丢进去跑，跑完就销毁，不影响你的主系统。平台提供沙箱，你只管投代码、收结果。

2.6

能力 4 · 双层记忆：平台库 + 本地偏好

这一步在做什么：让 Agent「记住」用户。分两层：平台记忆库（LongTermMemoryService）负责跨会话持久化——每轮前预检索历史记忆、追加进系统提示，每轮后保存；本地偏好记录「默认业务线/地域」当默认参数。还有短期改写——「那北京呢」自动补全成完整问题。
长期 · 平台库

LongTermMemoryService：每轮前 preload 检索注入系统提示、每轮后保存。与原 ADK 版 LongTermMemory 同后端。

长期 · 本地偏好

UserPreference：默认业务线/地域/间隔 + 最近 uid/isp，每次查询后更新，注入 Prompt。

短期 · 改写兜底

query_rewriter：「那北京呢」补全为完整问题；3s 超时回退原文；近期 2 轮兜底。

记忆注入（agent.py） # 每轮前预检索历史记忆，追加进系统提示 memories = await _preload_memory(user_id, user_message) if memories: sys_prompt += f"\n【记忆】{memories}" # compiled graph 无状态，人格随消息传： messages = [SystemMessage(sys_prompt), HumanMessage(query)]
每轮保存（agent.py） async def _save_to_memory(user_id, msg): if _memory_service is None: return # 记忆库未启用静默跳过 await _memory_service.add_session_to_memory(...)
📋 本节需要的环境变量（写进 .env）
KSADK_LTM_BACKEND 降级记忆库后端：设 sdk 接金山云 AICP；设 local 用纯内存（零平台依赖，适合先试）；不设则记忆库关闭（get_memory_service() 返回 None），主对话不受影响。
KSADK_LTM_NAMESPACE 可选记忆命名空间（隔离不同 Agent 的记忆），UUID 格式。控制台创建记忆库后获得。
KSADK_LTM_AGENT_ID 可选Agent ID，未在 AgentEngine 部署可留空。
KSADK_LTM_ENDPOINT 可选记忆库端点，内网用 aicp.inner.api.ksyun.com，避免公网探测抖动。
KSADK_LTM_TOP_K 可选每次注入的历史记忆条数，建议 5。
培训要点：记忆 = 平台库 + 本地偏好。优雅降级是记忆的灵魂：未配 KSADK_LTM_BACKEND 时 _memory_service 为 None，preload/保存都静默跳过，主对话不受影响。新手建议：先用 KSADK_LTM_BACKEND=local 零依赖跑通，再换 sdk。
📘 官方对应样例：基础 01-tutorials/memory/langgraph；进阶长任务恢复 long-task-resume/langgraph（演示 checkpoint / ResumeRun）。
2.7

能力 5 · 流式 SSE：真流式非伪流式

这一步在做什么：让回答像打字机一样一个字一个字蹦出来，而不是等全部生成完才一次性返回。「真流式」= 逐 token 推送，而且检索结果、工具过程、正文要分级下发，前端按类型渲染。
启用流式（agent.py） model = ChatOpenAI( ..., streaming=True, # 配合 astream_events ) # FastAPI 网关：SSE return StreamingResponse( generate(), media_type="text/event-stream", headers={Cache-Control: no-cache, X-Accel-Buffering: no})
七级事件协议（真实，与 ADK 版一致） data: {"type":"retrieval"} # 知识切片先出 data: {"type":"tool_calls"} # 工具过程 data: {"type":"mcp_result"} # 计费结果+Excel data: {"type":"sandbox_result"} # 算价步骤 data: {"type":"content_start"} # 正文开始 data: {"type":"content","data":"北京"}# 逐字 data: {"type":"done"} # 结束
培训要点：流式靠 LangGraph 的 astream_events（v2）逐 token 产出，ChatOpenAI(streaming=True) 是前提。事件按 retrieval/tool/mcontent 分级下发，前端按类型渲染（切片卡片、计费面板、打字机正文）。X-Accel-Buffering: no 防 Nginx 缓冲——新手常踩的坑：流式接好了却因反向代理缓冲，前端还是一坨一坨出现。SSE 事件契约与 ADK 版完全一致，前端无需改动。
第三篇

平台搭建：对接 ksadk，从本地到上云

Agent 写完后，要让平台能加载它、能配置它、能部署它、能观测它。本篇讲四件事：root_agent 入口契约、环境变量总表、三形态部署、Trace 可观测。

3.1

入口契约：暴露 root_agent，对接平台 runner

这一步在做什么：让平台能「找到并加载」你的 Agent。做法是在 agent.py 里定义一个模块级变量 root_agent，再在 agentengine.yaml 里用 entry_point + agent_variable 告诉平台去哪找、找哪个变量。这样你的 Agent 既能自带 FastAPI 外壳独立跑，也能交给平台 runner 托管。
agent.py · 模块级变量 # 模块级 root_agent：供 ksadk # 平台 runner 加载（getattr(module, "root_agent")） # LangGraph 框架下 root_agent 即 compiled graph root_agent = get_compiled_graph() # 两种运行形态共用同一工厂： # ① 平台 runner 托管 → 走 root_agent(compiled graph) # ② 自带 FastAPI → 走 routes_chat 的 astream_events # 工具/记忆/知识库能力完全一致
agentengine.yaml · 入口契约 name: luoluo framework: langgraph artifact_type: Container entrypoint: uvicorn main:app \ --host 0.0.0.0 --port ${PORT:-8122} workdir: backend port: 8122 health_path: /health entry_point: backend/agent.py # ★ 平台去这找 agent_variable: root_agent # ★ 加载 compiled graph ui: { profile: custom, path: / }
培训要点（平台对接核心）：平台 runner 通过 entry_point 找到 agent.py，用 getattr(module, agent_variable) 加载 root_agent。LangGraph 版下 root_agent 就是 create_react_agent 产出的 compiled graph。这是「自带外壳跑」与「平台托管跑」共用同一份 Agent 能力的关键——你只写一次 Agent，两种形态都能跑。

3.4

上云部署实操：命令与必填参数

这一步在做什么：把 Agent 部署到金山云 AgentEngine Serverless。三步走：build 打包代码 → launch 上传 + 创建云端产品 → dashboard 打开控制台。本节给出每条命令的完整用法、必填参数，以及实测踩过的坑。
前置准备（缺一不可）：① 金山云账号 ID（KSYUN_ACCOUNT_ID，纯数字，如 73408690）；② AK/SK（KSYUN_ACCESS_KEY/KSYUN_SECRET_KEY，AKLT 开头）；③ .env 已按 3.2 环境变量总表填好；④ 已安装 ksadk 与 agentengine CLI。这些都齐了再往下走。
第 1 步 · 打包代码 # 默认 code 模式：打包 zip + 依赖，本地生成 .agentengine/code_build/luoluo.zip agentengine build . # 可选：指定区域 / 强制重装依赖 KSYUN_REGION=cn-beijing-6 agentengine build . --no-cache # 可选：container 模式构建 Docker 镜像（需 KCR 凭证） agentengine build . --mode container \ --registry hub-cn-beijing-6.kce.ksyun.com --push
build 做了什么

① 扫描依赖生成清单 → ② 装 Linux x86_64 wheel（交叉构建）→ ③ 打包项目文件 + 依赖 + runtime 为 zip。产物约 200MB+，含完整运行时。默认不上传，加 --push 才传 KS3。

第 2 步 · 一键部署到 Serverless # 核心命令：build + 上传 KS3 + 创建云端 Agent 一条龙 KSYUN_ACCOUNT_ID=<账号ID> KSYUN_REGION=cn-beijing-6 \ agentengine launch . \ --target serverless \ --account-id <账号ID> \ --artifact-type Code # 探测配置（不实际部署，先看请求体对不对） agentengine launch . --target serverless \ --account-id <账号ID> --dry-run
launch 三阶段

① 准备构建环境（命中缓存则跳过重新 build）→ ② 上传 zip 到 KS3（断点续传）→ ③ 调 CreateAgentProduct 创建云端 Serverless 产品。成功后返回 Agent ID 与 Endpoint。

参数 / 变量必填填什么说明
launch 命令行参数
--target serverless必填部署目标，固定 serverless另可选 kcf / kce，默认即 serverless
--account-id必填金山云账号 ID（纯数字）也可用环境变量 KSYUN_ACCOUNT_ID 代替
--artifact-type Code推荐部署模式：Code（zip）/ Container（镜像）⚠️ 不指定时按 yaml 的 artifact_type 决定，yaml 是 Container 会自动切镜像模式（需 KCR 凭证）
--region可选区域，如 cn-beijing-6默认 cn-beijing-6
--name可选部署名称，默认取 yaml 的 name云端同名 Agent 会冲突，需先删旧的
--no-cache可选强制重新构建，不复用缓存改了依赖或代码后用
--dry-run可选只打印请求体，不实际部署排查参数问题用
必填环境变量（写进 .env 或命令前 export）
KSYUN_ACCOUNT_ID必填金山云账号 ID，纯数字launch 的 --account-id 兜底也用它
KSYUN_ACCESS_KEY必填金山云 AK，AKLT 开头。⚠️ 密钥上传 KS3 + 调平台 API 都用
KSYUN_SECRET_KEY必填金山云 SK，与 AK 配对。⚠️ 密钥同上
KSYUN_REGION推荐区域，如 cn-beijing-6不设用默认，建议显式指定
KSADK_AICP_ENDPOINT_MODE排障public / auto（默认）⚠️ 本地非内网环境建议设 public，否则 auto 可能误选内网地址导致请求到不了
KCR_PASSWORD仅镜像KCR 镜像仓库访问密码/Token。⚠️ 密钥仅 Container 模式需要，Code 模式不用
第 3 步 · 打开 Dashboard # 打开云端 Agent 控制台（默认浏览器） KSYUN_ACCOUNT_ID=<账号ID> agentengine dashboard open # 打开指定 Agent 的 Dashboard agentengine dashboard open <agent_id> # 部署后查看 Agent 状态 / 列表 agentengine agent list agentengine agent status <agent_id>
dashboard 能看到什么

Agent 运行状态、副本数、Endpoint、Trace 链路、资源消耗账单。launch 成功后会返回 agent_id，用它直接打开对应控制台。

完整一条龙（复制即用）：把 <账号ID> 换成你的金山云账号 ID，.env 填好后执行： 
export KSYUN_ACCOUNT_ID=<账号ID>
export KSYUN_REGION=cn-beijing-6
export KSADK_AICP_ENDPOINT_MODE=public      # 本地环境避免误连内网
agentengine build .
agentengine launch . --target serverless --account-id $KSYUN_ACCOUNT_ID --artifact-type Code
agentengine dashboard open
⚠️ 实测踩过的坑（部署失败先看这几条）：
1. CreateAgentProduct 返回 400「创建产品失败」：平台返回的错误被 CLI 简化，看不到根因。先用 --dry-run --output json 看完整请求体，再到金山云控制台查产品创建日志。
2. 同名 Agent 冲突（400「Agent 名称已存在」）：先 agentengine agent delete <id> -y 删旧的再 launch（当前无 update 子命令）。
3. 本地部署请求到不了内网：auto 模式可能误选 aicp.inner.api.ksyun.com，显式设 KSADK_AICP_ENDPOINT_MODE=public。
4. Container 模式报缺 KCR 凭证：要么补 KCR_PASSWORD，要么改用 --artifact-type Code 走 zip 部署（只需 AK/SK）。
5. build --dry-run 会真实构建：全局 --dry-run 对 build 子命令无效，仍会触发 docker 构建，别拿它当"只探测"用。

排错

常见报错排查：照着现象找原因

下面列了新手最常踩的坑，按「现象 → 原因 → 解决」组织。卡住时先在这里找匹配的现象。

启动阶段

这一步在做什么：服务起不来时，问题几乎都在这四个里——三个强校验必填变量没填、依赖没装全、.env 放错目录。报错信息会直接告诉你缺哪个。
现象原因 / 解决
SECRET_KEY 环境变量未设置，请设置一个强密钥config.py 强校验。SECRET_KEY 没填就启动不了。在 .env 里填一串随机字符串即可。
MCP_BILLING_URL 环境变量未设置
MCP_BILLING_BEARER 环境变量未设置		这两个也是强校验必填。MCP 计费是你这版要跑通的核心，必须配齐。
ModuleNotFoundError: No module named 'langgraph' / 'langchain_openai' / 'e2b' / 'email_validator'隐式/框架依赖没装。回到 2.1 节，把 requirements.txt 里 langgraph / langchain-openai / langchain-core / kingsoftcloud-sdk-python / e2b / openpyxl / email-validator 全装上。这类「静默失败」不会一次报全，建议直接 pip install -r requirements.txt。
.env 改了不生效config.py 只在启动时加载一次，且查找顺序是 ./.env → ../.env。改完要重启服务；确认 .env 放对目录（backend/ 下或项目根，取决于运行目录）。

知识库 / 记忆库（金山云 SDK 调用）

这一步在做什么：服务起来了但知识库/记忆库不工作，多半是凭证、端点、ID 三件事——AK/SK 配错、公网内网点选错、ID 复制不完整。
现象原因 / 解决
InnerAccount 报错 / 公网探测抖动端点自动探测选到了公网。KSADK_KB_ENDPOINT / KSADK_LTM_ENDPOINT 显式设成内网 aicp.inner.api.ksyun.com，并设 KSADK_KB_SCHEME=http / KSADK_LTM_SCHEME=http。
知识库返回空 / 没检索到① KSADK_KB_DATASET_ID 复制不完整（漏字符）；② AK/SK 没配对；③ 数据集里还没上传文档。去控制台确认数据集 ID 和文档索引状态。
403 / 鉴权失败AK/SK 不正确或无对应权限。检查 KSYUN_ACCESS_KEY/KSYUN_SECRET_KEY 是否配对、前后有无空格、账号是否有 AICP 访问权限。
记忆库没生效（Agent 不记得上次）查 KSADK_LTM_BACKEND 是否设了；设 sdk 还需 KSADK_LTM_NAMESPACE。get_memory_service() 返回 None 时 preload/保存都静默跳过。先用 local 验证机制，再换 sdk。

沙箱 / 模型 / 流式

这一步在做什么：功能层问题——算价拿不到结果、模型不回答、流式一坨一坨。这些大多是沙箱变量没配齐、模型 key 失效、或反向代理缓冲。
现象原因 / 解决
calculate_billing 返回 error JSON / 不算价沙箱变量没配齐：检查 KSADK_SANDBOX_TEMPLATE_ID + E2B_API_KEY。沙箱是降级的——不可用时主对话不崩，但算价拿不到结果。
沙箱执行超时含冷启动，单次可能较慢。调大 KSADK_SANDBOX_TIMEOUT（建议 120）。首次调用往往最慢（冷启动），后续会快。
模型不回答 / 报 401OPENAI_API_KEY 没填或失效；OPENAI_BASE_URL 指向的地址和 key 不匹配。确认 key 有效且 base_url 用对了对应平台。
流式不流（一坨一坨出现）先确认 ChatOpenAI(streaming=True) 且用 astream_events（v2）逐事件产出；反向代理（Nginx）在缓冲则加 X-Accel-Buffering: no（2.7 节已含）。同时确认前端用 fetch + ReadableStream 逐块读取。
litellm / openai 序列化告警openai 版本过高。requirements 里锁 openai>=1.0.0,<2.0.0（2.1 节已含，langchain-openai 同样依赖 openai<2）。
排查心法：记住「降级」机制——记忆库、沙箱、MCP、Trace 都是「配了才用，没配静默跳过」。真正会让应用起不来的只有三个：SECRET_KEY、MCP_BILLING_URL、MCP_BILLING_BEARER。启动能过、功能不对，就去对照本表查对应组件的变量。

官方样例速查：照着 ksadk-samples 跑一遍

金山云官方维护了一份样例仓库 ksadk-samples，覆盖知识库 / 记忆库 / 沙箱等能力，且每个能力都有 LangGraph 版样例。建议在动手搭络络前，先跑通对应的官方样例建立直觉——它就是络络每个能力的「最小可跑版」。

样例仓库结构

01-tutorials/ 基础教程

hello-world、tool-calling、memory，每个都提供 ADK/LangGraph/LangChain/DeepAgents 四框架版本。从零入门。

02-use-cases/ 场景用例

knowledge-base-rag、coding-agent、multi-agent-team 等真实场景，同样按框架分子目录。

运行方式（官方推荐 uv）：uv pip install -r requirements.txt → uv run agentengine run -i .（交互式）或 uv run agentengine web .（本地调试 Web UI）。最小 .env 只需 OPENAI_API_KEY + OPENAI_MODEL_NAME，平台能力未配时样例自动降级到本地，不会报错。

为什么先跑官方样例

① 验证环境

样例是最小可跑集，能确认你的 ksadk 安装、AK/SK、模型 key 都对，排除环境问题。

② 理解降级

官方样例在平台能力未配时会打印「缺失项 + 降级行为」，正好帮你建立 2.x 节讲的优雅降级直觉。

③ 对照络络

样例是单能力的「纯净版」，络络是把多能力组装进业务。先懂单能力，再看络络怎么组合。

建议路径：先跑 01-tutorials/hello-world/langgraph 确认能跑通 → 再跑 memory 和 knowledge-base-rag 两个对应络络核心能力的样例 → 最后看 agentengine-toolsets/langgraph 这份全景 demo 理解平台对接边界。跑通这几个，回来看络络代码就通透了。
